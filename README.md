# CUBIA: Columnar Unity-Based Immersive Analytics

Source code accompanying the submission *"How Should We Draw a Million Points in VR? A Comparative Benchmark of Unity Rendering Pipelines for Immersive Analytics"*.

CUBIA is a Unity 6 framework for VR scatterplots. Data are prepared on the desktop into a columnar binary format (`.cdataset`) and drawn by one of three interchangeable rendering back-ends. This repository contains the framework, the benchmark harness, the IATK comparison harness and the benchmark datasets used in the paper.

## Renderer names used in the paper

| Paper name | Unity component | Class |
|---|---|---|
| Instanced Mesh | GPU instancing (`Graphics.DrawMeshInstanced`) | `Assets/Scripts/Scatterplot/ScatterplotInstancedRenderer.cs` |

## Requirements

- Unity 6000.5.2f1, Universal Render Pipeline 17.5.0, OpenXR 1.17.1
- Windows 10/11, a PC-VR headset supported by OpenXR
- Python 3 with `pandas` and `numpy` (dataset preprocessing only)

## Datasets

Synthetic benchmark datasets with eight numeric dimensions (`Dim_0` … `Dim_7`) and an integer class label (`Label`), generated by `tools/dataset_generator/DummyDatasetGenerator.py` (`export_benchmark_tiers`): five Gaussian clusters in `Dim_0`–`Dim_2` (scikit-learn `make_blobs`, `random_state=42`) plus uniform noise in `Dim_3`–`Dim_7`. The benchmark maps `Dim_0`–`Dim_2` to X, Y and Z.

| Tier | CSV | `.cdataset` |
|---|---|---|
| 10^4 | included | included |
| 10^5 | included | included |
| 10^6 | not included (> 100 MB) | included |
| 10^7 | not included (1.5 GB) | not included (> 100 MB) |

To regenerate the tiers that are not included (writes `benchmark_tiers/benchmark_1e4.csv` … `benchmark_1e7.csv`; the 10^7 file is about 1.5 GB):

```bash
pip install numpy pandas scikit-learn
cd tools/dataset_generator
python -c "import DummyDatasetGenerator as g; g.export_benchmark_tiers()"
```

`Dim_0`–`Dim_2` and `Label` are seeded and reproduce the files used in the paper exactly; the noise columns `Dim_3`–`Dim_7` are unseeded and differ between runs, but are not mapped to any visual channel in the benchmark. (Running the script directly also writes a set of exploratory 100-dimensional datasets to `synthetic_datasets/`.)

`.cdataset` files live in `Assets/StreamingAssets/DataCSV/ProcessedData/`. To convert CSV files, place them in `Assets/StreamingAssets/DataCSV/` and run:

```bash
pip install pandas numpy
python Assets/Scripts/Data/preprocess_csv_columnar.py
```

## Running the benchmark

### Our three back-ends

1. Open `Assets/Scenes/VisualizerSceneTest.unity`. Its `BenchmarkingManager` holds the settings used in the paper: tiers 10^4–10^7, 20 builds, 60 warm-up frames, five 900-frame windows, 600 s cap per condition, randomised condition order.
2. Build with the build profile `Assets/Settings/Build Profiles/StandaloneBenchmarking.asset` (Windows, non-development).
3. Run the executable with the headset connected. Three chained sessions with a 60 s cool-down, as in the paper:
   ```
   CUBIA.exe -sessionIndex 1 -sessionCount 3
   ```
   Results are written as one long-format CSV per session to `<build folder>/BenchmarkResults/`.

Optional command-line overrides: `-framesPerWindow`, `-windows`, `-buildRepeats`, `-warmup`, `-maxSeconds`, `-session`.

### IATK (Single Mesh)

IATK (master branch, May 2023) is included under `Assets/IATK/` under its MIT licence (`Assets/IATK/LICENSE`). Its scripts depending on VRTK/Tilia and Mapbox were excluded, and its Standard-shader materials converted to URP Lit; its rendering code is unchanged. IATK reads the same `.cdataset` files through `IATKCDatasetSource`, since its own CSV data source cannot hold the 10^7-point file.

1. Generate the IATK benchmark scene (copies the benchmark scene, disables the CUBIA renderers and adds `IATKBenchmarkRunner`):
   ```
   Unity.exe -batchmode -quit -projectPath . -executeMethod DataViz.EditorTools.IATKBenchmarkBuild.SetupScene
   ```
2. Build it:
   ```
   Unity.exe -batchmode -quit -projectPath . -executeMethod DataViz.EditorTools.IATKBenchmarkBuild.Build -iatkOut "Builds/IATK/CUBIA.exe"
   ```
3. Run it with the same command-line arguments as above. The runner reads all trial settings from the scene's (disabled) `BenchmarkingManager`, so both harnesses use identical values; the CSV schema is the same, with `Pipeline = IATK`.

## Benchmark data and analysis

`analysis/results/` holds the raw per-session CSVs behind the paper (one long-format file per session; `RowType` is `frame`, `build`, `memory`, `env` or `timeout`):

- `benchmark_results_standalone_s{1,2,3}_*.csv`: Instanced Mesh, CPU Particles and GPU Particles
- `benchmark_results_IATK_standalone_s{1,2,3}_*.csv`: Single Mesh (IATK)

`analysis/paper_figures.R` reduces frames to window medians, window medians to one value per session, and reports mean ± SD over the three sessions. It writes Figures 3–5 and a table of the capacity and per-point columns of Table 2 (`tab_capacity.tex`) to `analysis/results/paper_labels/`:

```
cd analysis
Rscript paper_figures.R results
```

Requires R with `dplyr`, `tidyr`, `readr`, `stringr`, `purrr`, `ggplot2`, `scales` and `patchwork`.

Note: the `xrRefreshHz` field in the `env` rows is a single reading taken when each condition starts and occasionally shows 30 or 45 Hz while the runtime recovers from the previous condition. The analysis uses only the per-frame timings in the `frame` rows; wherever a renderer meets the budget, these sit at the 11.1 ms (90 Hz) vsync interval, including in the conditions with such a reading.
